# 场景 1: 原型草图

在画布上绘制草图、线框图、UI 布局、流程图、架构图等。这是最基础的画布使用场景。

## 适用信号

命中以下信号时使用本场景：
- 用户要画草图、线框图、布局图
- 用户要可视化工作流、流程、架构
- 用户要在画布上展示 UI 结构或布局方向
- 用户提到"画个图"、"画布上画"、"草图"等

## 绘图原则

### 图应该"说话"

好的草图不是把文字放进方框，而是让结构本身传达含义。检验标准：如果去掉所有文字，形状和连接的结构本身是否仍能传达概念？

### 选择合适的视觉模式

根据要表达的概念选择结构：

| 概念 | 视觉模式 | 结构 |
|------|----------|------|
| 一对多（来源、分发） | Fan-out | 中心元素 → 辐射到多个目标 |
| 多对一（汇聚、合成） | Convergence | 多个输入 → 合并到一个输出 |
| 层级结构 | Tree | 父子分支 + 自由文本标签 |
| 循环过程 | Spiral/Cycle | 元素形成环路 |
| 转换过程 | Assembly Line | 输入 → 处理 → 输出 |
| 对比 | Side-by-Side | 两列并排 |
| 时间线 | Timeline | 竖线/横线 + 标记点 |

### 减少不必要的容器

不是每段文字都需要框。默认用自由文本，只在框有语义含义时才加（如：表示边界、容器、分组）。

目标：不超过 30% 的文本元素放在容器内。

### 用字号和颜色建立层级

- **标题**: fontSize 28-32, 加粗
- **副标题**: fontSize 20-24
- **正文**: fontSize 16-18
- **注释**: fontSize 12-14, 浅色

## 创建 Excalidraw 元素

读取 `references/element-templates.md` 获取各类元素的 JSON 模板。

### 分段构建大型草图

对于包含多个区域的复杂草图，分段构建：

1. 先创建整体骨架（标题、区域边界）
2. 逐个区域填充内容
3. 添加区域间的连接箭头
4. 最后统一检查间距和对齐

### ID 和 seed 管理

- ID 格式：`<timestamp>-<random>`，如 `"1778336862857-19qh357"`
- 不同区域的 seed 用不同的数值段避免冲突
- 区域 1: seed 100xxx, 区域 2: seed 200xxx

### 布局建议

- **水平间距**: 200-300px
- **垂直间距**: 100-150px
- **主体元素尺寸**: 180×90（标准）, 300×150（重要）, 120×60（次要）
- **最重要的元素周围留 200px+ 的空白**
- **流向**: 从左到右或从上到下

## 嵌入原型节点

如果草图中需要嵌入已有原型，创建 `type: "embeddable"` 元素，`link` 指向 `http://localhost:<port>/prototypes/<name>`，`customData.title` 写原型标题。具体字段见 `element-templates.md`。

> 原型节点的 `link` 中的端口号可以通过 `axhub-make canvas info` 获取，或者从其他已有的原型节点中读取。

## 嵌入文档节点

创建 `type: "embeddable"` 元素，`customData.type` 设为 `"axhub-doc"`，`link` / `previewUrl` 指向 URL 编码后的 Markdown 文件 API。具体字段见 `element-templates.md`。

## 添加批注

给任何元素添加批注：在 `customData.annotation` 写批注文本，并更新 `customData.annotationUpdatedAt`。

## 完成后

1. 写入修改后的 `.excalidraw` 文件
2. 依赖画布热更新同步到浏览器；不要默认执行刷新命令
3. 告知用户主要改动和可确认的画布链接（如果能确定）
