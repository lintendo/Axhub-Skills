## 路由原则

先判断研究结论将支持哪个市场的决策，再选择平台。不要以提问语言、研究者所在地或某个平台是否方便访问代替市场判断。

记录四个范围字段：

| 字段 | 含义 |
| --- | --- |
| `decision_market` | 结论最终服务的市场 |
| `target_users` | 用户所在地区、角色和细分群体 |
| `market_mode` | `china-only`、`global-only` 或 `hybrid` |
| `locality_drivers` | 使需求具有地域性的因素 |

## 三种市场模式

### China-only

当最终决策只服务中国市场时选择。以下因素会进一步决定信源与分析维度：

- 中国法律、监管、数据驻留、实名或内容治理要求
- 微信、企业微信、钉钉、飞书、支付宝等本地生态集成
- 国内应用商店、安卓渠道、支付、发票、物流或售后体系
- 政府采购、招投标、国企或本地企业采购流程
- 中国城市层级、地区差异、节日、家庭结构或消费语境

海外材料可以放入“背景类比”，但不能提高中国需求的置信度。

### Global-only

当产品、渠道和决策明确只面向海外市场时选择。使用海外社区、评测、应用商店、职位和一手资料。中国材料只在用户要求跨市场参考时加入。

### Hybrid

在以下情况选择：

- 产品同时服务中国和海外市场
- 研究通用工作流，例如协作、效率、开发工具或 AI 使用
- 需要判断某个海外机会是否也适用于中国
- 需要识别全球共性和中国特有约束

建立两条独立证据流：

```text
China evidence  -> China themes  -\
                                  -> cross-market comparison
Global evidence -> Global themes -/
```

分别计算样本量、频次和置信度，再总结一致点、差异点和待验证迁移假设。

## 决策步骤

1. 明确用户、场景和最终决策覆盖的市场。
2. 若决策同时覆盖中国和海外，选 `hybrid`；若只服务中国，选 `china-only`；若只服务海外，选 `global-only`。
3. 列出可能改变需求的地域因素，用于选择各市场的信源和比较维度，不用它替代市场范围判断。
4. 若范围不明且不同选择会改变结论，询问：“这次研究主要支持中国市场、海外市场，还是需要比较两者？”
5. 在报告开头公开模式、理由、时间范围和未覆盖市场。

## 最低采集组合

### China-only

- 至少三个独立来源。
- 尽量覆盖两种以上来源类型：社区、评论/投诉、访谈/工单、交易/应用评价、招聘/采购、官方资料。
- 至少一个来源能提供用户逐字表达。

### Global-only

- 至少三个独立来源，避免全部来自同一评论聚合站。
- 兼顾原话、实际行为或工作流信号。

### Hybrid

- 每个市场至少两个来源类型；重要结论仍以每个市场三个独立来源为高置信门槛。
- 不用跨市场样本凑足单一市场的最低样本。

## 常见误判

- “用户说中文”不等于产品只面向中国。
- “功能在全球都存在”不等于用户工作流没有本地差异。
- “海外已有成熟产品”不等于中国用户接受同样的价格、渠道或隐私权衡。
- “国内平台讨论少”不等于没有需求，可能是平台不可索引、用户在私域或产品尚未形成品类词。
- “同一观点在多个媒体出现”不等于多源验证，先检查是否来自同一稿件或发布会。
